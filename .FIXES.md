# Vex - Τεκμηρίωση Διορθώσεων

Αυτό το αρχείο περιγράφει τα προβλήματα που εντοπίστηκαν στον scanner και πώς τα επιλύσαμε.

---

## Fix 1: Scope Enforcement

### Τι ήταν το πρόβλημα;
Το `Config` struct είχε ένα `Scope` field (λίστα από hostnames που επιτρέπεται να σκαναριστούν), αλλά **ποτέ δεν γεμούσε** από το CLI. Κανένα `-scope` flag δεν υπήρχε στο `main.go`. Αυτό σήμαινε ότι η `inScope()` function επέστρεφε πάντα `true` (επειδή η λίστα ήταν κενή), και ο scanner μπορούσε να ακολουθεί links σε οποιοδήποτε domain — ακόμα και εκτός του target.

**Παράδειγμα προβλήματος:**
Αν σκανάρεις `http://example.com` και η σελίδα είχε link στο `http://google.com`, ο scanner θα ακολουθούσε και αυτό το link.

### Πώς το επιλύσαμε;
Προσθέσαμε `-scope` flag στο `main.go`. Αν ο χρήστης δεν το ορίσει, το scope παίρνει αυτόματα το hostname του `-target`. Έτσι ο scanner σκανάρει **μόνο** το target domain by default.

```go
// main.go
scope := flag.String("scope", "", "Comma-separated list of allowed hostnames")

// Αν δεν δοθεί scope, χρησιμοποιούμε το hostname του target
if *scope != "" {
    config.Scope = strings.Split(*scope, ",")
} else {
    parsed, _ := url.Parse(*target)
    config.Scope = []string{parsed.Hostname()}
}
```

## Fix 2: Goroutine Leak on Context Cancellation

### Τι ήταν το πρόβλημα;
Στο `engine.go`, η `Run` function χρησιμοποιούσε έναν loop για να συλλέξει τα αποτελέσματα από ένα channel:

```go
// Παλιός κώδικας - ΠΡΟΒΛΗΜΑΤΙΚΟΣ
for i := 0; i < len(requests); i++ {
    responses = append(responses, <-results)
}
```

Ο `<-results` είναι **blocking** — περιμένει μέχρι να έρθει αποτέλεσμα. Αν ο χρήστης πατούσε Ctrl+C και το context γινόταν cancelled, ο loop **δεν σταματούσε**. Ο scanner κόλλαγε και δεν τερμάτιζε ποτέ.

### Πώς το επιλύσαμε;
Αντικαταστήσαμε το blocking receive με ένα `select` statement που ακούει και στο `ctx.Done()`. Έτσι αν το context ακυρωθεί, ο loop βγαίνει αμέσως.

```go
// Νέος κώδικας - ΣΩΣΤΟΣ
for i := 0; i < len(requests); i++ {
    select {
    case resp := <-results:
        responses = append(responses, resp)
    case <-ctx.Done():
        return responses // Βγαίνει αμέσως στο Ctrl+C
    }
}
```

## Fix 3: Page Checks Firing Once Per Parameter

### Τι ήταν το πρόβλημα;
Checks όπως `HeaderCheck`, `CookieCheck`, `ServerCheck`, `DirListCheck` δεν ελέγχουν κάποιο συγκεκριμένο parameter — ελέγχουν τη **σελίδα** στο σύνολό της. Όμως υλοποιούσαν το `VulnCheck` interface που τους έδινε ένα `InjectionPoint`. Αν μια σελίδα είχε 5 parameters, αυτά τα checks τρέχανε **5 φορές** για την ίδια σελίδα, στέλνοντας 5 ίδια GET requests. Τελείως περιττό.

### Πώς το επιλύσαμε;
Φτιάξαμε ξεχωριστό `PageCheck` interface στο `types.go` που παίρνει μόνο URL αντί για `InjectionPoint`:

```go
// Νέο interface στο types.go
type PageCheck interface {
    Name() string
    Run(ctx context.Context, url string, eng RequestDoer) []Finding
}
```

Και ενημερώσαμε το `RunAll` στο `checks.go` να χρησιμοποιεί `map[string]bool` για deduplication — κάθε URL ελέγχεται **μία φορά** μόνο:

```go
seen := make(map[string]bool)
for _, point := range points {
    if seen[point.URL] {
        continue // Παράλειψη αν το URL έχει ήδη ελεγχθεί
    }
    seen[point.URL] = true
    for _, check := range pageRegistry {
        f := check.Run(ctx, point.URL, eng)
        findings = append(findings, f...)
    }
}
```

## Fix 4: No Baseline Before Injection (False Positives)

### Τι ήταν το πρόβλημα;
Τα injection checks (XSS, SQLi, Path Traversal, CMDi) έστελναν ένα payload και ελέγχανε αν η απάντηση περιείχε κάποιο evidence. Όμως **δεν συνέκριναν με την αρχική σελίδα**. Αν το evidence υπήρχε ήδη στη σελίδα φυσιολογικά, ο scanner θα το ανέφερε ως εύρεση — **false positive**.

**Παράδειγμα:** Αν μια σελίδα περιείχε ήδη τη λέξη "syntax error" στο κείμενό της, το SQLi check θα το ανέφερε ως SQL Injection λανθασμένα.

### Πώς το επιλύσαμε;
Πριν στείλουμε το payload, κάνουμε ένα **baseline request** με το αρχικό URL. Κάνουμε report finding μόνο αν το evidence εμφανίζεται στο injected response αλλά **όχι** στο baseline:

```go
// Baseline - αρχικό request
baseline := eng.Do(ctx, types.Request{URL: point.URL, Method: point.Method})

// Injected - request με το payload
resp := eng.Do(ctx, types.Request{URL: injectedURL, Method: point.Method})

// Report μόνο αν το evidence δεν υπάρχει στο baseline
if strings.Contains(body, sig) && !strings.Contains(string(baseline.Body), sig) {
    // Πραγματικό finding!
}
```

Για το CMDi (time-based), ελέγχουμε αν το injected request πήρε **πολύ περισσότερο χρόνο** από το baseline:

```go
if resp.Elapsed > 4*time.Second && resp.Elapsed > baseline.Elapsed*2 {
    // Πραγματικό finding!
}
```

## Fix 5: Form-Aware Injection (FormParams)

### Τι ήταν το πρόβλημα;
Δύο ξεχωριστά προβλήματα στον crawler:

**Πρόβλημα 5α:** Ο crawler έβαζε `Method: "POST"` σε **όλα** τα form inputs, ανεξάρτητα από το τι έλεγε το HTML attribute `method` της `<form>`. Αν η φόρμα χρησιμοποιούσε GET (που είναι και το default), τα checks έστελναν POST requests που αγνοούσαν τα parameters.

**Πρόβλημα 5β:** Όταν ο scanner δοκίμαζε injection σε ένα parameter (π.χ. `id`), **δεν συμπεριλάμβανε** τα υπόλοιπα fields της ίδιας φόρμας στο request (π.χ. `Submit=Submit`). Πολλές εφαρμογές εκτελούν τη λογική τους **μόνο** αν όλα τα required fields είναι παρόντα. Χωρίς αυτά, η εφαρμογή απλά επέστρεφε την κενή φόρμα χωρίς να εκτελέσει καμία SQL query.

### Πώς το επιλύσαμε;

**5α - Method fix:** Ο crawler τώρα διαβάζει το `method` attribute της `<form>` και default σε GET:

```go
case "form":
    method := "GET" // Default είναι GET
    for _, attr := range n.Attr {
        if attr.Key == "method" && strings.ToUpper(attr.Val) == "POST" {
            method = "POST"
        }
    }
```

**5β - FormParams fix:** Προσθέσαμε `FormParams map[string]string` στο `InjectionPoint` struct. Ο crawler συλλέγει **όλα** τα inputs μιας φόρμας μαζί, και για κάθε injection point περνά τα υπόλοιπα fields ως `FormParams`:

```go
// Για κάθε input της φόρμας, τα υπόλοιπα inputs πάνε στο FormParams
for _, input := range formInputs {
    others := map[string]string{}
    for _, other := range formInputs {
        if other.name != input.name {
            others[other.name] = other.value
        }
    }
    c.points = append(c.points, types.InjectionPoint{
        Parameter:  input.name,
        FormParams: others, // Τα υπόλοιπα fields
        ...
    })
}
```

Και όλα τα injection checks συμπεριλαμβάνουν τώρα τα `FormParams` στα requests:

```go
params := parsed.Query()
for k, v := range point.FormParams { // Προσθήκη των υπόλοιπων fields
    params.Set(k, v)
}
params.Set(point.Parameter, payload) // Το injection
```

## Σύνοψη

| Fix | Αρχείο | Αποτέλεσμα |
|-----|--------|------------|
| Scope enforcement | `cmd/vex/main.go` | Ο scanner δεν βγαίνει εκτός target domain |
| Context cancellation | `internal/engine/engine.go` | Ctrl+C τερματίζει αμέσως |
| PageCheck interface | `pkg/types/types.go`, `internal/checks/` | Page checks τρέχουν μία φορά ανά URL |
| Baseline requests | Όλα τα injection checks | Μειωμένα false positives |
| FormParams | `internal/crawler/crawler.go`, όλα τα injection checks | Σωστή υποβολή φορμών |
